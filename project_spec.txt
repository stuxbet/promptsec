Overview
During April, your group will complete a one-month defensive cybersecurity project focused on AI systems, AI-enabled cyber defense, or AI agent security. This project is not about offensive hacking. Your work must stay in a defensive context and focus on how organizations can securely deploy, monitor, protect, and validate AI systems and AI-assisted workflows.

Many organizations are deploying internal LLMs, retrieval systems, copilots, and AI agents. These technologies create important cybersecurity and privacy concerns, including data leakage, prompt injection, insecure retrieval, excessive permissions, weak logging, privacy risks, unsafe automation, and poor validation of AI-generated results. Your group will study one of these problems from the defender’s perspective and propose, test, or evaluate controls that reduce risk.

This project will produce:

a public GitHub repository showing steady progress,

a professional final report in PDF format,

a short presentation with findings and recommendations.

Project Goal
Your group will act as a junior cybersecurity defense team for an organization deploying or using AI systems.

Your job is to:

identify what must be protected,

analyze realistic threats,

propose or implement defensive controls,

validate whether those controls reduce risk,

explain what residual risk remains.

Approved Project Domains
Your project must stay within one of the following defensive domains.

1. AI for Cyber Defense
Use AI to improve defensive security operations.

Possible directions:

LLM-assisted SOC alert triage

AI-based phishing detection and explanation

AI-generated threat intelligence brief with source validation

AI-assisted secure configuration and hardening recommendations

2. Security of LLM Applications
Focus on protecting organizational LLM systems.

Possible directions:

secure internal LLM deployment risk assessment

prompt injection defense for a RAG chatbot

privacy leakage testing for enterprise LLM use

defensive analysis of model inversion or membership inference risks

secure retrieval and safe data handling for organizational chat systems

3. AI Agent Security
Focus on protecting AI agents that use tools, memory, or automation.

Possible directions:

least-privilege design for AI agents

human-in-the-loop validation for AI agent actions

secure memory and context management

logging, monitoring, and audit trails for AI agents

4. Governance and Secure Deployment
Focus on security architecture, policy, and deployment planning.

Possible directions:

secure enterprise LLM deployment blueprint

AI acceptable use and data handling security policy

security evaluation framework for organizational AI tools

Safe Project Rules
Your project must follow these rules:

Use only approved lab environments, simulations, or synthetic data.

Do not use real private data, real secrets, or real credentials.

Do not test public systems or unauthorized systems.

Do not target real users.

Do not attempt to bypass security on external services.

If you simulate sensitive data, it must be clearly labeled as synthetic or dummy data.

Projects that violate these rules will not be accepted.
